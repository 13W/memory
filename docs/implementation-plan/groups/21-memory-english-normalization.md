# Группа 21 — English normalization of durable memory (post-v0)

Третья группа, открытая после закрытия `T00–T17` (`G17: PASS`) по явному продуктовому решению —
`docs/adr/0010-memory-english-normalization.md`. Не переоткрывает ни один гейт `G00–G20`. Цель:
текст durable-записи приводится к английскому локальной генеративной моделью, которая в продукте
уже есть, и в вектор уходит именно английский вариант; канонический `memory_entry.text` при этом
не меняется никогда. Перевод текста запроса в эту группу **не входит** — он отложен до честного
замера (`T21-10`).

Ссылки: ADR-0010; ADR-0006 (рантайм локального генератора); spec 03 §1.4 `[FIXED]` (нет writable
cross-DB `ATTACH`), §2.5; spec 08 §3 `[FIXED]` (текст меняется только через `edit`/audit), §4
`[FIXED]` (`local_only` → локальный генератор), §5, §6 `[FIXED pipeline]` + as-built X-010/X-011;
spec 10 §3; spec 12 §2/§4 `[FIXED]` (untrusted-текст, purge); spec 14 §7;
`crates/store/src/memory/{mod,entry,op}.rs`; `crates/store/src/{subjects,cache/embedding}.rs`;
`crates/memory/src/recall/{pipeline,dense,lexical}.rs`; `crates/embed/src/{backfill,gen_pool,contract}.rs`;
`crates/local-rag/src/daemon/{lifecycle,jobs,idle,consolidation_trigger}.rs`;
`crates/xtask/src/memory_recall_bench/`; D-067, D-068.

Формат карточек — по `TASK-TEMPLATE.md`, структура группы — как в группах 18/20. Один таск —
одна итерация — один коммит.

## Диагноз (контекст для исполнителя — прочитать до начала)

1. **Связь «запись ↔ вектор» — вычисляемый хэш, а не FK.** `subject_memory_entry(memory_id, text)`
   (`crates/core/src/identity/domain.rs:230`) считается независимо в трёх местах:
   `crates/store/src/subjects.rs:270` (что ожидается от backfill'а),
   `crates/embed/src/backfill.rs:703` (что реально эмбеддится),
   `crates/memory/src/recall/dense.rs:211` (что ищется в кэше). Стоит определениям разойтись —
   dense-нога бесшумно вернёт ноль попаданий по затронутым записям. Это главный риск группы;
   `T21-02` покупает **структурную** гарантию, а не соглашение.
2. **`D-067`: dense-нога уже сегодня теряет кандидатов.** `dense_leg` ограничивает чтение кэша
   числом кандидатов (`dense.rs:198-201`), а ридер отдаёт строки по всем memory-записям стора —
   любых скоупов, любых состояний, плюс устаревшие хэши — `ORDER BY subject_hash LIMIT ?3`
   (`crates/store/src/cache/embedding.rs:307-320`). На живом сторе владельца: 86 строк кэша против
   44 кандидатов → ожидание ≈ 22 из 44. Нормализация удваивает число строк на запись, то есть
   усугубляет дефект. `D-067` обязан быть закрыт до `T21-05`.
3. **Memory-векторы пересчитываются только попутно с индексацией воркдерева.** Единственный
   продовый вызов `run_backfill` — `crates/local-rag/src/indexing/mod.rs:180` внутри
   `project_generation`. Стор без enrolled-проектов не пересчитает memory-векторы никогда, поэтому
   фоновый таск обязан сам закрывать вектор (`T21-05`), а не надеяться на цикл индексации.
4. **Единственный `GeneratorPool` на процесс.** `crates/local-rag/src/daemon/lifecycle.rs:504-506`,
   D-054: `LlamaBackend` — процессный синглтон, повторный `build_best_effort_pool` даёт
   `BackendAlreadyInitialized` и молчаливую деградацию до пустого пула на весь uptime. Новый
   потребитель обязан получить **клон того же `Arc`**.
5. **Уроки консолидации применяются превентивно.** D-050 (retry-storm на детерминированном сбое),
   D-057 (классификация mechanical/transient), D-024 (`JobGuard` только на время активного тика) —
   форма dead-letter, backoff и врезки воркера копируется, а не изобретается. Отдельно: отсутствие
   генератора — свойство окружения, а не записи, и обязано прерывать тик, а не помечать записи
   failed.
6. **`[FIXED]`-границы.** `memory_entry.text` неприкосновенен (08 §3); конвейер recall 08 §6 эта
   группа **не меняет** (меняется только текст, представленный вектором) — амендмент понадобился бы
   лишь `T21-10`; untrusted-текст, идущий в промпт переводчика, требует adversarial-тестов (12 §4).
7. **`D-068`: бенч недетерминирован.** `crates/xtask/src/memory_recall_bench/run.rs:275-276` минтит
   `memory_id` через `SystemUuidV7` при общем `created_at = 1_000`, поэтому тай-брейк
   `(score desc, created_at desc, memory_id)` решается случайным UUID. Из-за этого `store_en` и
   `both_en` — прогоны с побайтово идентичным входом на `en-en` — разошлись на одном запросе, и
   именно этот пол-балла составляет весь их overall-разрыв. Замер `T21-09` без `D-068` бессмыслен.

Порядок работ: регистрация (`T21-00`), затем блокирующий `D-067`, затем хранилище
(`T21-01` схема, `T21-02` эффективный текст), затем компоненты (`T21-03` детектор,
`T21-04` переводчик), затем проводка (`T21-05` запись, `T21-06` фоновый таск), затем поверхности
(`T21-07` privacy, `T21-08` наблюдаемость), затем измерение (`D-068`, `T21-09`), затем владельческое
решение по query-стороне (`T21-10`), затем гейт.

## D-067 — Dense-нога читает векторы по точным ключам, а не слепым `LIMIT`-сканом

- **Зависит от:** `T21-00` (только регистрацией строки в `DEVIATIONS.md`).
- **Спецификация:** spec 08 §6 (dense-нога); spec 03 §4.2.
- **Результат:** dense-нога получает вектор для **каждого** кандидата, у которого он есть в кэше,
  независимо от того, сколько посторонних memory-строк лежит в `embedding_cache`.
- **В scope:** новый ридер `embeddings_for_subjects(conn, subject_kind, representation_id, &[&str])`
  в `crates/store/src/cache/embedding.rs` (чанкованный `IN (…)` с запасом по лимиту параметров
  SQLite, детерминированный порядок); `dense_leg` переходит на него и теряет параметр `cap`;
  doc-комментарий `embeddings_for_subject_kind` получает предупреждение либо функция удаляется,
  если других вызывающих нет.
- **Не в scope:** нормализация; изменение fusion, порядка и формата ответа.
- **Тесты:** regression — в кэше 2N memory-строк, кандидатов N, кандидат с максимальным
  `subject_hash` обязан быть отранжирован (тест обязан падать на текущем коде); границы чанкования
  (>999 и >1998 кандидатов); поведение не изменилось, когда строк ровно столько же, сколько
  кандидатов; повреждённая строка по-прежнему пропускается поэлементно.
- **Приёмка:** regression-тест красный до правки и зелёный после; строка `D-067` переведена в
  `resolved`.

## D-069 — Детерминированный отказ apply уходит в дедлеттер, а не крутит модель вечно

- **Зависит от:** `T21-00` (только регистрацией строки в `DEVIATIONS.md`). Ортогональна остальным
  карточкам группы: трогает consolidation-раннер, а не нормализацию.
- **Спецификация:** spec 08 §4 (шаги 4–5 и as-built заметки T14-07/D-047/D-050/D-051); spec 04 §4
  (`stale_runs`/`retry_run`, аренда); spec 12 §4 (вывод модели — недоверенные данные).
- **Результат:** окно, чей ответ роутера содержит повторённый `observation_id`, применяется с
  первой попытки; любой детерминированно воспроизводимый отказ apply уходит в дедлеттер за
  ограниченное число попыток, а не крутит локальную модель бесконечно.
- **В scope:** дедупликация `evidence_observation_ids` с сохранением порядка внутри `apply_run` для
  обеих веток (`ProposeCandidate`, `runner.rs:359-384`; `Materialize` через `resolve_evidence`,
  `runner.rs:253-288`) — store-примитивы `propose_candidate`/`insert_candidate_evidence` при этом
  не меняются; `RunOutcomeError::Write(WriteError::Sqlite(_))` с нарушением constraint'а
  классифицируется `Mechanical`, а не `Transient` (`runner.rs:705-721`); потолок для `Transient` —
  N подряд одинаковых `last_failure_fingerprint` уводят ран в дедлеттер; as-built правка заметки
  D-050 в `docs/specification/08-memory.md` §4.
- **Не в scope:** нормализация текста и вся остальная группа 21; промпт и поведение роутера;
  churn индексации; уровни логирования; ретеншн поколений.
- **Тесты:** regression — роутер отдаёт `ProposeCandidate` с дважды повторённым `observation_id`
  ⇒ `run_once` = `Applied`, в `candidate_evidence` ровно одна строка (тест обязан падать на
  текущем коде); то же для `Materialize` против `memory_evidence`; classification — constraint-
  нарушение из write-транзакции ⇒ `FailureKind::Mechanical`, `next_retry_at` не выставляется,
  `stale_runs` при том же `BUILD_ID` ран не возвращает; страховка — N подряд одинаковых
  транзиентных fingerprint'ов ⇒ ран перестаёт быть retry-eligible; идемпотентность — повторный
  apply того же окна не создаёт вторую строку evidence.
- **Приёмка:** regression-тесты красные до правки и зелёные после; на живом сторе владельца ран
  `01a01648-…` применяется с первой попытки после рестарта демона, и за 10 минут в
  `logs/daemon.<дата>.log` нет ни одной строки `consolidation resume run … failed`; строка `D-069`
  в `DEVIATIONS.md` переведена в `resolved`.
- **Приёмка на живом сторе — отложена решением владельца (2026-08-19):** демон в этой итерации не
  поднимался и продакшн-бинарь не пересобирался, поэтому живая половина приёмки не выполнена. Ран
  `01a01648-42b3-797d-bebb-3e6cba2bf7a5` (сессия `10c0ce45-…`, окно `26115..26117`) остаётся
  запаркован с fingerprint'ом `0.0.0-76-gb14fb3a`; первая же пересборка продакшн-бинаря даёт ему
  ровно одну попытку, которая и будет живым подтверждением. Кодовая половина приёмки
  (красные-до/зелёные-после regression-тесты) выполнена полностью.

## T21-01 — Схема v14 `memory_text_normalization` + репозиторные операции

- **Зависит от:** `T21-00`.
- **Спецификация:** spec 03 §2.5 (`[SPEC]`-амендмент — новая таблица, прецедент X-006);
  spec 13 §3; `crates/store/src/migrate/mod.rs:189-215` (текущий максимум версии — 13).
- **Результат:** миграция 14 и модуль `crates/store/src/memory/normalization.rs` без единого
  потребителя.
- **В scope:** DDL (`memory_id` PK с FK `ON DELETE CASCADE`, `status IN ('ready','skipped','failed')`,
  `source_text_sha256`, `normalized_text`, `source_language`, провенанс — `normalizer_model_id`,
  `prompt_version`, `normalizer_version`, `attempt_count`, `last_error`, `next_attempt_at`,
  `created_at`, `updated_at`, `CHECK ((status='ready') = (normalized_text IS NOT NULL))`, индекс по
  `(status, next_attempt_at)`); регистрация в `ALL` + абзац в его doc-комментарии;
  `upsert_normalization` с условным UPDATE-сторожем по текущему тексту, `normalization_for`,
  `entries_needing_normalization`, `normalization_counts`, `delete_normalization`; константы
  `CURRENT_NORMALIZER_VERSION`, `MAX_NORMALIZATION_ATTEMPTS`; backoff через существующий
  `transient_backoff_delay_ms` (второй кривой не заводить).
- **Не в scope:** эффективный текст и любые изменения ридеров (`T21-02`); переводчик; демон.
- **Тесты:** миграция на свежем сторе и на реальном v13; чексумма заморожена; список версий в
  `crates/store/tests/migrate.rs` обновлён (13 → 14); FK отвергает неизвестный `memory_id` и
  откатывает транзакцию; каскад убирает строку; CHECK отвергает `ready` без текста, не-`ready` с
  текстом и неизвестный `status`; `upsert` идемпотентен; `upsert` отказывает при уехавшем тексте и
  ничего не пишет; предикат/порядок/лимит очереди (терминальные не попадают, `failed` до
  `next_attempt_at` не попадает, устаревший `normalizer_version` попадает); `schema_audit` зелёный.
- **Приёмка:** `cargo test -p local-rag-store --test migrate --test migrate_fixtures --test memory`
  зелёные; `local-rag doctor` на апгрейженном сторе показывает store_version 14.

## T21-02 — `EffectiveText`: единственная точка хэширования memory-субъекта

- **Зависит от:** `T21-01`.
- **Спецификация:** spec 03 §1.2/§4.2; spec 08 §6; spec 10 §3 (as-built: аргумент subject-функции
  memory — эффективный текст).
- **Результат:** вычислить memory-субъект вне одного модуля структурно невозможно; оба ридера
  получают текст и его нормализацию одним стейтментом.
- **В scope:** модуль `crates/store/src/memory/effective_text.rs` (тип с приватным полем и без
  публичного конструктора, общие константы SQL-джойна и колонок, общий маппер строки, чистая
  табличная `decide`, `memory_entry_subject_hash(&EffectiveText)`); `all_memory_entries_with_text`
  → `…_with_effective_text`; джойн в `recall_candidates_for_scope`/`recall_candidate_by_id` и поле
  `RecallCandidate.embed_text` (поле `text` остаётся оригиналом — показ, лексика, бюджет);
  механические правки `subjects.rs:270`, `backfill.rs:703`, `dense.rs:211`; doc-комментарий
  `subject_memory_entry` («для хранимой записи — только через `memory_entry_subject_hash`»).
- **Не в scope:** лексическая нога; фоновый таск; любые записи в новую таблицу.
- **Тесты:** табличный тест `decide` по всем случаям (нет строки / хэш сошёлся / хэш не сошёлся /
  `skipped` / `failed` / перевод из пробелов / терминальная запись); parity-тест
  `crates/store/tests/memory_normalization_parity.rs` — множество хэшей из
  `memory_entry_subject_keys` против множества из `recall_candidates_for_scope` (включение,
  побайтовое равенство, отсутствие фан-аута, сохранённый `ORDER BY memory_id`); lint-тест
  `crates/store/tests/memory_subject_lint.rs` — `subject_memory_entry` встречается в непроверочном
  коде ровно в двух файлах; существующие тесты `subjects`/`backfill`/`dense` зелёные без ослабления
  ассертов.
- **Приёмка:** `cargo test -p local-rag-store -p local-rag-embed -p local-rag-memory` зелёные;
  факт «вызов `subject_memory_entry` из `crates/memory` не компилируется» зафиксирован в evidence.

## T21-03 — Детерминированный детектор письменности

- **Зависит от:** `T21-00`.
- **Спецификация:** ADR-0010 §Decision 8/§Consequences (заявленное ограничение).
- **Результат:** `crates/memory/src/normalize/detect.rs` — чистые `script_class`/`script_stats`,
  без модели, сети и состояния.
- **В scope:** снятие нейтрального шума (fenced/inline код, URL/email/пути, uuid/hex/base64-подобные
  токены, идентификаторы с `_`/`::`/внутренней заглавной/`()`, цифры и пунктуация); NFD с
  отбрасыванием combining marks; счёт латиницы против не-латиницы по алфавитным символам; две
  именованные константы (`MIN_ALPHABETIC_CHARS`, `NON_LATIN_RATIO`) с обоснованием в doc; явное
  заявленное ограничение «различаем письменности, не языки» в doc-комментарии модуля.
- **Не в scope:** любая интеграция; определение конкретного языка; n-gram/ML-модели.
- **Тесты:** табличная фикстура ≥30 строк (ru/en проза; код-свитч «проза + идентификаторы + путь»;
  чистый код; только URL/uuid; строки короче порога; de/fr/pl → `English` с комментарием
  «declared limitation»; CJK/арабский/иврит; эмодзи; пусто); по именованному тесту на каждую
  константу с граничным входом; диакритика (`é`, `ü`, `ł`) считается латиницей; идемпотентность;
  отсутствие паники на всех строках `fixtures/memory-recall/corpus.json`.
- **Приёмка:** таблица ожиданий воспроизводится тестом один-в-один; ограничение присутствует в doc
  дословно.

## T21-04 — Компонент перевода

- **Зависит от:** `T21-03`.
- **Спецификация:** spec 08 §4 `[FIXED]` (`local_only`); spec 10 §1; spec 12 §4 п.5 (adversarial);
  ADR-0006; уроки D-050/D-057.
- **Результат:** `crates/memory/src/normalize/translate.rs` — `translate(pool, policy, req)`, чистая
  `validate`, `classify_translate_failure`, `TRANSLATOR_VERSION`, типизированные ошибки.
- **В scope:** короткое замыкание passthrough по детектору (ноль вызовов генератора); промпт сырой
  строкой по образцу `crates/memory/src/prompt.rs:27` с четырьмя few-shot примерами, один из
  которых — инъекционный payload, переведённый как инертный текст; user-сообщение сериализуется
  serde как `{"src": …}`; ответ — одна строка `{"en": …}` с `deny_unknown_fields`; валидация
  (`FinishReason::Length` → `Truncated` до разбора, снятие markdown-fence через существующий
  `parse::strip_markdown_fence`, полоса длины относительно источника, скриптовая проверка выхода,
  жёсткий байтовый потолок без молчаливого усечения); `max_tokens` от `estimate_tokens` источника с
  потолком; pre-flight по длине входа; классификация mechanical/transient/`Unavailable`.
- **Не в scope:** chunked-перевод длинных записей (явно, с обоснованием в doc); любая запись в БД;
  фоновый таск; перевод запроса.
- **Тесты** (на `ScriptedGenerator`, без реальной модели): happy path ru→en; ответ в fence; валидный
  префикс + мусорный хвост; пустой/пробельный ответ → `Refused`; `FinishReason::Length` →

  модели (`LOCAL_RAG_TEST_MODEL_HOME`, громкий SKIP, без `#[ignore]`).
- **Приёмка:** каждая ветка ошибки достижима тестом; ни один тест не требует сети, модели или
  wall-clock; adversarial-набор поимённо перечислен в as-built-заметке к spec 12 §4.

- **Зависит от:** `T21-07` (только регистрацией строки в `DEVIATIONS.md`).
