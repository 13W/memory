# Группа 19 — MCP adoption: агент должен реально пользоваться инструментами

Цель: устранить причины, по которым Claude Code-агенты, имея подключённый plugin, не вызывают
`recall`/`search_code`/`remember`, — не меняя `CLAUDE.md`/`AGENTS.md` проектов, где plugin
установлен (жёсткое продуктовое ограничение: plugin не имеет права трогать репозитории
пользователей — существующий guardrail «plugin packaging must not modify users' repositories»).

Ссылки: spec 11 §2 (tool surface), §3.1–3.2 (hooks), §5 (`additionalContext`); spec 07 §2;
spec 13 (distribution); `crates/local-rag/src/daemon/mcp/{tools,instructions}.rs`;
`crates/local-rag-hook/src/{main,recall}.rs`; `plugin/hooks/hooks.json`; `plugin/.mcp.json`;
D-039/D-041 (прецедент caller-facing текстовых правок), DEVIATIONS.md.

## Диагноз (контекст для исполнителя — прочитать до начала)

Наблюдение D-041 (агент часами не вызывал `recall`, имея полный доступ) объясняется
композицией четырёх механизмов; правка одних только `SERVER_INSTRUCTIONS` (D-041) адресует
самый слабый из них:

1. **MCP Tool Search / deferred loading (Claude Code ≥ 2.1.7).** Когда суммарный объём
   определений MCP-инструментов превышает ~10 % контекстного окна, Claude Code не вставляет
   их в контекст: модель видит только голые имена в system-reminder и должна сама «захотеть»
   подгрузить инструмент через `ToolSearch`. Отложенный инструмент спонтанно почти никогда не
   вызывается. Наш каталог — 17 инструментов с развёрнутыми описаниями — заметный вклад в
   пробитие порога (порог считается по всем серверам пользователя сразу).
2. **Конкуренция со встроенными инструментами.** Системный промпт Claude Code прямо
   предписывает `Grep`/`Glob`/`Read`, и модель дополнительно натренирована на них. Первые
   предложения наших описаний описывают *что делает* инструмент, но не *когда выбрать его
   вместо встроенного* — в такой конкуренции нейтральное описание проигрывает всегда.
3. **`SERVER_INSTRUCTIONS` — слабый канал.** Claude Code доставляет поле `instructions`
   (issue anthropics/claude-code#3312 закрыт), но это один статический блок в начале большого
   системного промпта; к середине сессии его поведенческий вес около нуля. Claude Desktop и
   claude.ai/web поле по-прежнему выбрасывают. Единственный канал, который гарантированно
   оказывается рядом с точкой принятия решения на каждом ходу, — per-prompt
   `additionalContext` из `UserPromptSubmit`-hook, и он у нас уже есть (spec 11 §3.2/§5), но
   сейчас продаёт только память, а не маршрутизацию инструментов.
4. **Стоимость/надёжность старта.** `plugin/.mcp.json` и оба плеча `hooks.json` в фолбэке
   зовут `npx --yes --package=@13w/memory` — холодный `npx` ходит в registry, в
   офлайн/прокси-окружениях молча падает (сервер «не подключён» → инструментов просто нет),
   а в норме добавляет секунды. Первое плечо использует `${CLAUDE_PLUGIN_DATA}` —
   переменную, существование которой в актуальных версиях Claude Code надо подтвердить
   (документированная — `${CLAUDE_PLUGIN_ROOT}`); если она пуста, первое плечо падает всегда
   и каждый hook-вызов уходит в медленный npx-фолбэк.

Из этого следует порядок работ: сначала то, что модель реально видит на каждом ходу
(T19-02), затем то, что она видит в каталоге (T19-01), затем надёжность доставки самого
сервера (T19-03), затем дополнительные каналы (T19-04) и измеримость (T19-05). T19-06 —
опциональное жёсткое принуждение, требует владельческого решения.

Перед стартом: вставить очередь T19-01…G19 в `PROGRESS.md` (после G18/post-v0 блока),
вести статусы `[~]`/`[x]` и evidence по общему контракту. Один таск — одна итерация — один
коммит.

## T19-01 — Trigger-style описания инструментов + бюджет каталога

- **Зависит от:** —.
- **Спецификация:** spec 11 §2 `[SPEC]`; `crates/local-rag/src/daemon/mcp/tools.rs`.
- **Результат:** каталог `tools/list`, в котором (а) первое предложение каждого из пяти
  рабочих инструментов — критерий выбора против встроенного аналога, (б) суммарный размер
  каталога ограничен тестом.
- **В scope:**
  - Переписать первые предложения описаний `search_code`, `recall`, `get_file_context`,
    `project_overview`, `remember` в форме «Use INSTEAD of <builtin> when …»:
    `search_code` — вместо `Grep`/`Glob`, когда нужен поиск по смыслу или идентификатор
    неизвестен; `get_file_context` — вместо повторного `Read`/поиска по уже найденному файлу;
    `project_overview` — вместо серии `ls`/`Glob` при ориентации в незнакомом репозитории;
    `recall` — до первого чтения файлов; `remember` — в момент появления долговечного факта.
    Остальной текст описаний сохранять/сокращать, не расширять.
  - Сократить описания административных инструментов (`list_memory_candidates`,
    `approve/reject/edit_memory_candidate`, `edit_memory`, `retract_memory`,
    `merge_memories`, `stats`, `health`, `give_feedback`) до 1–2 предложений: они не
    участвуют в рабочем цикле, но их токены приближают порог деферрала для всего каталога.
  - Новая константа-бюджет (например `MAX_CATALOG_BYTES`, выбранное и задокументированное
    `[SPEC]`-число, не выведенное) + unit-тест: `serde_json::to_string(&catalog())` не
    превышает бюджет. Это регрессионный щит от разрастания каталога обратно.
  - Обновить as-built текст spec 11 §2 (тот же класс правки, что D-039/D-041).
- **Не в scope:** имена/параметры инструментов (spec-fixed), диспетчер, `SERVER_INSTRUCTIONS`
  (уже переписаны в D-041; трогать только если тест на подстроку сломает сокращение — тогда
  синхронизировать минимально).
- **Тесты:** существующие строковые тесты каталога остаются зелёными
  (`catalog_advertises_all_seventeen_v0_tools_with_the_spec_fixed_names` и соседние); новый
  тест бюджета; `cargo test -p local-rag --lib daemon::mcp` + `--test mcp_contract`.
- **Приёмка:** fmt/clippy чисто; фиксация в PROGRESS.md фактического размера каталога
  до/после (в байтах) как evidence.

## T19-02 — Tool-routing трейлер в per-prompt `additionalContext`

- **Зависит от:** T19-01 (формулировки должны совпадать с описаниями).
- **Спецификация:** spec 11 §3.2 `[SPEC]`, §5 `[SPEC]` + `[FIXED: empty recall ⇒ no output]`;
  `crates/local-rag-hook/src/recall.rs`; `crates/memory/src/recall/format.rs`; spec 12 §4.
- **Результат:** непустой recall-блок, инжектируемый на `SessionStart`/`UserPromptSubmit`,
  завершается фиксированной байт-детерминированной строкой-маршрутизатором, называющей
  инструменты по имени (вида: «Tools for this workspace: search_code (semantic code search —
  prefer over Grep when meaning matters), recall (run before first file read), remember
  (call the moment a durable fact surfaces). If these tools are deferred, load them via
  tool search first.»). Точный текст — часть результата задачи и фиксируется в spec 11 §5
  as-built.
- **В scope:** формат-писатель (`format_additional_context` или обёртка на стороне hook —
  выбрать место так, чтобы байт-детерминизм и существующие fixture-тесты формата остались
  осмысленными); обновление spec 11 §5 as-built; фиксация текста трейлера константой.
- **Не в scope / ограничение `[FIXED]`:** «Empty recall ⇒ no output at all» — `[FIXED]`.
  Трейлер при **пустом** recall НЕ выводить. Если владелец сочтёт нужным нудж и при пустой
  памяти (первые сессии нового пользователя — ровно тот случай, где адопция хуже всего), это
  изменение `[FIXED]` → отдельное design-revision-решение; зафиксировать вопрос в
  DEVIATIONS/idea.md как открытый пункт, не реализовывать молча.
- **Тесты:** byte-exact fixture-тесты формата (обновить golden-байты осознанно, в том же
  коммите, с объяснением); тест «пустой recall — по-прежнему ни байта»; существующие
  `recall_rpc.rs`-тесты hook'а зелёные.
- **Приёмка:** fmt/clippy/focused-тесты чисто; в evidence — полный байтовый вид нового блока.

## T19-03 — Надёжный и быстрый запуск: hooks.json / .mcp.json

- **Зависит от:** —(параллельно T19-01/02).
- **Спецификация:** spec 11 §3.1 `[FIXED]` (fail-open, no daemon spawn from hooks); spec 13;
  `plugin/hooks/hooks.json`; `plugin/.mcp.json`; `npm/memory/bin/*`; T17-02 acceptance
  (hook cold-start < 50 ms).
- **Результат:** первое плечо запуска (hook и MCP) разрешается в уже установленный
  платформенный бинарь без сети; `npx --yes` остаётся только последним фолбэком; переменная
  окружения первого плеча подтверждена против актуальной документации Claude Code plugins.
- **В scope:**
  - Аудит `${CLAUDE_PLUGIN_DATA}`: подтвердить по актуальной документации plugins, что
    переменная существует и указывает туда, где реально лежит `bin/local-rag-hook`; если нет —
    заменить на рабочий механизм (`${CLAUDE_PLUGIN_ROOT}`-относительный путь к shipped
    резолверу) во всех семи hook-событиях.
  - `.mcp.json`: вместо голого `npx` — shipped в plugin лёгкий launcher (node-скрипт,
    переиспользующий resolve-логику `npm/memory/src`), который пробует: локально
    установленный `@13w/memory` → платформенный бинарь по известному пути → `npx --yes` как
    последний фолбэк. Никакой установки в репозиторий пользователя.
  - Замер и фиксация cold-start обоих путей (hook — существующий < 50 ms бюджет; MCP-launcher —
    выбрать и задокументировать бюджет).
- **Не в scope:** сам протокол proxy↔daemon; автозапуск демона из hooks (запрещён `[FIXED]`).
- **Тесты:** `plugin/test/*` (manifest-validate, hooks-list, paths-per-platform, cold-start,
  install-uninstall, no-writes-in-sample-repo) — расширить на launcher; негативный тест
  «registry недоступен, локальный бинарь есть → сервер стартует».
- **Приёмка:** все plugin-тесты зелёные; evidence — замеры cold-start до/после.

## T19-04 — Plugin skill «memory-first workflow»

- **Зависит от:** T19-01 (единая терминология).
- **Спецификация:** spec 11 §2 (routing-таблица инструментов как источник контента);
  формат Claude Code plugin skills (`plugin/skills/<name>/SKILL.md`).
- **Результат:** plugin поставляет skill, чьё описание (оно попадает в системный промпт
  всех сессий с установленным plugin — ещё один канал, не требующий правки CLAUDE.md
  проектов) триггерится на задачи поиска по коду/памяти проекта, а тело даёт компактную
  таблицу маршрутизации: какой инструмент вместо какого встроенного, признак деферрала и
  команда подгрузки через tool search.
- **В scope:** SKILL.md (описание-триггер + тело ≤ ~1 страницы), регистрация в
  plugin-манифесте, если требуется схемой; обновление `plugin/README.md`.
- **Не в scope:** slash-команды, agents, MCP-изменения.
- **Тесты:** manifest-validate/install-uninstall/no-writes расширить на skills-директорию.
- **Приёмка:** plugin-тесты зелёные; в evidence — итоговый текст description.

## T19-05 — Наблюдаемость адопции: счётчики `tools/call` в `stats`

- **Зависит от:** —.
- **Спецификация:** spec 11 §2 (`stats`); `crates/local-rag/src/daemon/mcp/dispatch.rs`.
- **Результат:** демон считает вызовы `tools/call` по имени инструмента (per-session и
  агрегат с момента старта демона, in-memory — без изменения схемы state.sqlite) и отдаёт их
  в `stats`; это делает поведенческий эффект группы измеримым — «агент стал звать `recall`»
  превращается из впечатления в число (ограничение D-041 — «поведенческая комплаенс-проверка
  не автоматизируется юнит-тестом» — снимается хотя бы на уровне наблюдаемой метрики).
- **В scope:** счётчик в диспетчере; расширение ответа `stats` (+ as-built spec 11 §2);
  unit-тест инкремента; фикстурный тест формы ответа.
- **Не в scope:** персистентность счётчиков, аудит-таблицы, дашборд (группа 18).
- **Тесты:** `cargo test -p local-rag --lib daemon::mcp` + `--test mcp_tools`.
- **Приёмка:** fmt/clippy/тесты чисто.

## T19-06 — [РЕШЕНИЕ ВЛАДЕЛЬЦА] Opt-in PreToolUse-гейт

- **Зависит от:** T19-02; **блокирована до явного продуктового решения** — не реализовывать
  по умолчанию.
- **Суть:** hook на `PreToolUse` для `Grep|Glob`, который **один раз за сессию** возвращает
  deny с причиной «call recall / search_code first (local-rag)», строго fail-open, включаемый
  только явной пользовательской настройкой (env/plugin-конфиг), по умолчанию выключен.
  Это единственный механизм настоящего принуждения (hooks исполняются механически, а не
  «читаются» моделью), но он вторгается в чужой workflow — поэтому только opt-in.
- **Статус в плане:** зафиксировать как открытый пункт в DEVIATIONS.md/idea.md со ссылкой на
  это описание; реализация — отдельной задачей после решения. Если решение «нет» —
  задокументировать отказ, задача закрывается без кода.

## Приложение — диагностика на стороне пользователя (не задачи агента)

Передать пользователям plugin'а (README): `/mcp` — подключён ли сервер вообще; `/context` —
inline или deferred наши инструменты; `claude --debug` — ошибки старта `npx`;
`ENABLE_TOOL_SEARCH=false` (или `auto:N`) в user-level настройках (`~/.claude/settings.json`,
env) — обход деферрала без правки чужих проектов; сабагенты с явным списком `tools:` в
frontmatter не получают MCP-инструменты, если те не перечислены. Claude Desktop и claude.ai/web
не доставляют `SERVER_INSTRUCTIONS` — там работают только описания инструментов и hooks.
